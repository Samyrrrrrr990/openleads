# OpenLeads 5.2.x Housekeeping and 5.3 "Simple" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 5.2.1 (housekeeping, licensing page, growth autopost) and then 5.3 (say it, see the plan, run it; Today; an approve queue; reply triage; a pre-send hook; about ten visible commands).

**Architecture:** 5.3 adds four small modules on top of the existing engine, with no rewrites:
- `ask.py` turns a request into a `Plan`, which is a `Query` or a 5.2 workflow graph.
- `workspace/drafts.py` holds first emails waiting for approval (a new `drafts` table, migration 5).
- `outreach/replies.py` stores and triages reply text in the activity timeline.
- `today.py` composes the existing stats, tasks, drafts and replies into one briefing.

The CLI, MCP server and dashboard Home are thin surfaces over `today.py` and `ask.py`. The pre-send hook sits inside `outreach/sender.send_drafts`, the one place every real send passes through.

**Tech Stack:** Python 3.8+ stdlib only (sqlite3, argparse, urllib, subprocess), plain-JS dashboard (no build), pytest.

**Spec:** `docs/superpowers/specs/2026-11-10-openleads-5.3-5.5-design.md` (sections 5, 6, 10, 11)

All paths are relative to the repo root, `~/Desktop/Project - Website/automation`. Run tests with `python -m pytest` from the repo root. If pytest is missing, `pip install pytest` in a venv first.

## Global Constraints

- `requires-python = ">=3.8"`: no `match`; keep `from __future__ import annotations` in new modules.
- Core stays stdlib-only: `dependencies = []` in `pyproject.toml` does not change.
- Every hidden command keeps working with its existing flags and output; existing tests keep passing.
- Database changes only through `openleads/schema.py` `@register(5, ...)`, additive, never editing migrations 1 to 4.
- Nothing sends without `--live` or an explicit approval; tests never touch the network (`tests/conftest.py` already refuses HTTP).
- Email copy OpenLeads writes: no em dashes or en dashes; about 110 to 125 words for a first email; personalize with something specific or not at all; plain layout.
- Version strings that must agree at release: `pyproject.toml`, `openleads/__init__.py`, `npm/package.json`, `server.json` (two places).
- Never commit a real person's name or address. License replies to companies go outside the repo.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A typo'd command** (`openleads fnd "x"`, `openleads peple`) must say "unknown command, did you mean `find`?" and exit 2. It must not run as a plain-English search. Test in Task 13.
2. **A queued draft whose contact replied, bounced or unsubscribed** after it was queued must not send when approved. It ends `skipped` with the reason. Test in Task 7.
3. **Approving the same draft twice** (two surfaces, or a double keypress) sends it once. The second approve returns an error and sends nothing. Test in Task 7.
4. **A pre-send hook that hangs or answers garbage** must time out and follow `presend_hook_on_error`; it must never stall the batch or crash it. Test in Task 6.
5. **Non-interactive runs** (piped, cron, CI): `openleads today` and `openleads "..."` must never wait for a keypress. They print and exit. A plan that needs confirmation prints "re-run with --yes". Tests in Tasks 11 and 13.
