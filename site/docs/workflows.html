Workflows

A workflow is an automation drawn as a graph, the way n8n draws one: a trigger starts it, nodes find or load leads, filters route them, and outreach, workspace and export nodes act on them. Leads travel along the connections as items, one lead per item, so you can see exactly how many reached each step.

openleads web        # then open Workflows (under Automate) in the sidebar
openleads workflow templates
openleads workflow new miami --from local-business-outreach

Everything runs on your machine. A test run never sends, exports, notifies or changes your workspace, so you can try any workflow safely.

#The editor

Do thisHow
Add a nodeAdd node (or press A), search, then click a node or drag it onto the canvas. With a node selected, the new one is placed after it and connected.
Connect two nodesDrag from an output port (the dot on a node's right edge) onto another node. Drop on empty canvas to pick the next node from the list. From the keyboard, use Connections in the inspector.
MoveDrag a node, or select it and use the arrow keys (Shift moves further).
Pan and zoomDrag the empty canvas, hold Space and drag, or scroll. ⌘/Ctrl + scroll zooms; Fit or 0 frames the whole graph.
Edit a nodeClick it. The inspector shows its settings as a form, its connections, what to do if it fails, and the output of the last run.
DeleteSelect a node or a connection and press Delete, or use the inspector.
Duplicate a node⌘D / Ctrl+D.
Undo, redo⌘Z and ⌘⇧Z (Ctrl+Z, Ctrl+Y).
SaveSave or ⌘S. Problems (a missing audience, a loop, a Send with no Write before it) are listed in the inspector and marked on the node.

On a phone the graph is shown as a read-only list of steps in run order, with the last run's counts. Animations follow your system's reduced-motion setting.

#Test run and run history

Test run saves the workflow, runs it as a dry run and streams progress: each node lights up while it works, shows items in → items out when it finishes, and connections show how many items passed along them. Branches that received nothing stay dark. The Run log tab shows every step; History lists earlier runs. Click a run to put its counts back on the canvas, then click a node to see sample items from that run (who, which company, email evidence, the drafted subject).

#Activate, live, pause

  • Active lets the workflow's triggers fire on the scheduler. Install the scheduler once with openleads schedule on; see Timed runs.
  • Send for real on scheduled runs (in the workflow settings, shown when no node is selected) decides what Send does on those runs. Off, Send previews. On, it sends inside your warmup cap, suppression list and business hours.
  • Paused workflows don't fire. Items waiting in a Wait step stay parked and continue once you activate the workflow again.

#Copy one

Duplicate opens an unsaved copy of the current workflow, including your latest edits. The name starts with <name>-copy; if that is taken it uses <name>-copy-2, then -3, and so on. An untitled workflow becomes workflow-copy. The original stays unchanged, and the copy starts with no run history. Duplicating doesn't save or run anything, and is unavailable while a save or test run is in progress.

#Node catalog

Items are lead dicts: email, name, title, organization, domain, tier, evidence, confidence, fit score, stage, seniority, industry, phone and so on, the same fields openleads find --format json prints.

#Triggers

NodeWhat it does
ManualRuns when you press Test run, run it from the CLI, or call it over MCP.
ScheduleRuns on a schedule: weekdays 9am, every 2h, mon,wed 14:00, or cron like 0 9 * * 1-5.
New leadsSearches on a schedule and passes on only leads at companies it hasn't seen before (a watcher inside a workflow). The first real run remembers everything it finds.
Reply receivedFires for contacts who replied since the last run. It can scan your inbox first (IMAP); a run with no replies ends quietly and isn't logged.

#Leads

NodeWhat it doesSettings
Find leadsSearches the sources that fit your sentence, verifies every address and saves the leads to People.Audience, count, deliverable only, location, industry, job title, seniority
Load contactsPulls contacts already in your workspace.Stage, tag, list, minimum fit, last emailed (never, ever, more than N days ago), limit
Enrich CSV or listFinds and verifies emails for people you already know.Rows from incoming items, a CSV file or a list; deep search
Look up companyReads each company's homepage once: industry, size, phone, socials, tech stack.Companies per run
Verify emailsRe-checks each address and updates its tier and confidence.Skip ones that already have a tier

#Logic

NodeOutputsWhat it does
Filter (if)true, falseConditions on lead fields: tier, evidence, fit grade or score, email confidence, seniority, department, stage, industry, title, company, country, city, size, source, tags, has a phone, has LinkedIn, contacted before. Match all or any.
Split by tiersafe, risky, badRoutes each lead by its email tier.
Skip contactedDrops duplicates, suppressed and do-not-contact addresses, anyone emailed (ever, or in the last N days), anyone in a sequence, and optionally all but one lead per company.
LimitKeeps the first N, optionally the best first by fit or email confidence.

#Outreach

NodeWhat it does
Write emailDrafts a short, plain-text, spam-checked email for each lead with an address, with your AI key when one is set, or from a saved template.
WaitHolds items for days (and hours), optionally until business hours. Items wait in the database, so nothing needs to stay open: the scheduler wakes them on its next run, and anyone who replied, bounced or opted out meanwhile is dropped.
SendSends each draft from your mailbox. It always respects the warmup cap and suppression list, previews unless the run is live, and live sends outside business hours wait for the next send window. Needs a Write email before it.

#Workspace

NodeWhat it does
Add to listAdds each contact to a people list, creating the list if needed.
Enroll in sequenceEnrolls each contact in a sequence; the sequence's own rules apply.
Set stageMoves each contact to a stage.
Create taskOne task per contact: call, email, LinkedIn or to-do. Titles can use {{first_name}}, {{company}}, {{title}}. Due: now, today, tomorrow, +3d, mon or a date.
TagAdds or removes tags.

#Output

NodeWhat it does
ExportCSV, JSON or NDJSON file, Google Sheets (CSV), a webhook (n8n, Zapier, Make), Notion, Airtable or HubSpot. Test runs never export.
NotifyA desktop notification, a JSON POST to a webhook (Slack, Discord, ntfy), or both. {count} and {workflow} fill in.

Every node has If it fails: Stop the run (default), or Continue with other branches, which marks the run as partial and lets unrelated branches finish.

#Templates

TemplateWhat it does
local-business-outreachWeekday mornings: find local businesses, skip anyone already emailed, keep one per company, write and send to the safe ones, list the risky ones for review.
founder-outreachFind founders, keep the decision makers, email them and queue a LinkedIn task for the next day.
inbound-replyOn a reply: good-fit contacts move to Interested and get a call task today; others get tagged.
weekly-digest-sheetsEvery Monday: companies you haven't seen before, looked up, written to a Sheets-ready CSV, with a notification.
re-engage-unresponsiveWeekly: contacts quiet for 30+ days get a check-in; no reply in 5 days becomes a call task.
enrich-csv-hubspotBy hand: enrich a CSV, push safe contacts to HubSpot, list the rest for review.
drip-with-follow-upFind, email, wait three business days, then a call or LinkedIn task for anyone who didn't reply.

New workflows from templates start paused and not live.

#From the terminal

openleads workflow list                         # workflows and recipes
openleads workflow show miami                   # nodes in run order, problems
openleads workflow run miami                    # test run: nothing is sent
openleads workflow run miami --live             # real run: Send sends
openleads workflow export miami > miami.json
openleads workflow import miami.json --name miami-2   # imports arrive paused
openleads workflow activate miami               # or: pause
openleads workflow runs miami                   # recent runs with counts
openleads runs                                  # all scheduled jobs, workflows included

openleads drip (what the scheduler runs) wakes due Wait items and fires the triggers of active workflows. A drip without --live test-runs them and leaves waiting items where they are.

#Recipes are workflows too

Every recipe from openleads recipe add appears in the list as the graph it is: Schedule → Find leads → Split by tier → Write email → Send, with Export and the risky branch when the recipe has them. Recipes keep running exactly as before, and openleads recipe … still works. Editing that graph saves back to the recipe; add a step a recipe can't express and saving turns it into a full workflow (keeping when it last ran, so it doesn't fire twice).

#Over MCP

AI assistants connected with openleads mcp get list_workflows and run_workflow. run_workflow is a test run unless it is called with mode: "run", and it only sends with live: true as well.

#The API behind the editor

The dashboard uses /api/workflows (list), /api/workflows/get, /catalog, /templates, /runs, /run, /export, and POSTs to /save, /validate, /delete, /flags, /new, /import and /run (which streams NDJSON node events). They follow the dashboard's rules: loopback only, JSON bodies only, and cross-site requests are refused. Only saved workflows can run for real.

Note: the dashboard only listens on 127.0.0.1. Export, Notify and webhook steps are the places where lead data leaves your machine, and only to the destinations you configured.
