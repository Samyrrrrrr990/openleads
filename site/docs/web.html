The local web dashboard

bash
openleads web                 # → http://127.0.0.1:8787
openleads web --port 9000     # custom port
openleads web --no-open       # don't auto-open a browser
openleads demo                # the same dashboard on an invented demo workspace

A full sales workspace in your browser — prospecting, a people and company database, lists, sequences, tasks, deals, templates, analytics and workflows — running on the same engine and the same local database as the CLI.

#Local-first, by construction

  • stdlib only. The server is a ThreadingHTTPServer from Python's standard library (openleads/web/server.py). No Flask, no Node, no build step.
  • Bound to localhost. It listens on 127.0.0.1, not reachable from your network.
  • Pre-built UI. The app is plain ES modules and CSS committed under openleads/web/static/ and shipped in the wheel. End users need no toolchain.
  • No external requests from the page. A strict same-origin Content-Security-Policy blocks third-party scripts, styles and fonts. System fonts, no CDN, no analytics: nothing phones home.

#Records and deep links

Every record has its own URL, so you can bookmark or share a view on your own machine: #/people/jane@acme.com, #/companies/acme.com, #/sequences/3, #/deals/7, #/templates/2. Filters live in the URL too: #/people?stage=interested&tier=safe, #/activity?show=replies.

#Command palette and shortcuts

Press ⌘K (Ctrl+K) or / anywhere to search people and companies, jump to a page, or run an action (new task, deal, sequence, template or list; import a CSV; start the task queue; find new people for what you typed).

#Light and dark

The interface follows your system theme; the moon/sun button (or T) pins one. It respects prefers-reduced-motion and works down to phone width.

#Security

The dashboard can send email from your mailbox, so it treats every other website open in your browser as hostile:

  • Localhost only. It binds 127.0.0.1 and refuses any request whose Host header isn't a loopback name, which stops DNS-rebinding attacks. Add names with OPENLEADS_ALLOWED_HOSTS=myhost.lan if you put it behind your own proxy.
  • No cross-site requests. Requests marked cross-site by the browser (Sec-Fetch-Site), or carrying an Origin other than the dashboard's own (including Origin: null from sandboxed frames and file:// pages), get 403.
  • JSON only. Every write must be Content-Type: application/json (415 otherwise), which a plain HTML form on another site can't send. Bodies over 25 MB get 413; malformed JSON gets 400.
  • Can't be framed. X-Frame-Options: DENY and frame-ancestors 'none'.
  • Strict headers. Same-origin CSP with no inline scripts, nosniff, Referrer-Policy: no-referrer, same-origin opener and resource policies.
  • Secrets stay put. Stored chmod 600 on disk, shown masked in the UI, never sent back to the browser in full. Static files are path-traversal guarded.

If you want it beyond localhost (e.g. a home server), put it behind your own authenticated reverse proxy and allow its host name. OpenLeads deliberately ships no login because it's built to run on the machine you're sitting at.
